# 店舗・会社・加盟店まわりの回帰確認チェックリスト

「更新中・画面点滅」不具合の原因調査で、system_admin(管理者自身)のアカウントだけで動作確認して
「問題なし」と判断していたことが、実際に他ユーザーで起きていた不具合の発見を遅らせた。今後、
店舗選択・会社選択・加盟店閲覧・権限判定に関わる変更を行うときは、実装後に必ずこのチェックリストを
確認する。

## 確認対象ロール

system_adminだけでは不十分。最低限、以下4ロールそれぞれで確認する（招待ユーザーのテストアカウントを
各ロールぶん用意しておくこと）。

- system_admin
- company_admin
- store_manager
- staff

## 確認する状態遷移

各ロールについて、以下の一連の流れをコード上で（または可能なら実機で）追跡する。

1. ログイン
2. 店舗表示（所属店舗が正しく表示されるか、他社・他店舗のデータが混ざらないか）
3. 店舗切替（複数店舗所属ロールの場合。store_managerは自分の担当店舗以外に切り替えられないこと）
4. ページ移動（売上・日次入力・ダッシュボード・損益表・店舗設定など、店舗依存の各ページ）
5. 再読み込み（選択していた店舗・月が保持されるか、無効なIDが残っていないか）
6. ログアウト → 再ログイン（本来の所属会社・店舗へ戻るか、加盟店閲覧状態が残っていないか）

## 特に見るポイント

- `useEffect`の依存配列に、その`useEffect`自身が`setAppState`で書き換えるフィールドが含まれていないか
  （循環参照 → 無限ループの典型パターン）。
- `appState.currentCompanyId` / `selectedStoreId` が、`appState.companies` の中に実在するかどうかを
  必ず確認したうえで使っているか（存在しないIDのまま以降の処理に渡していないか）。
- RLSでデータ取得が0件・エラーになった場合に、無限リトライにならず、有限回数で止まって
  ユーザーに分かる形で復旧できるか（`HYDRATE_MAX_AUTO_RETRY_ATTEMPTS`、`src/App.jsx`参照）。
- 加盟店閲覧（INTRO）中の状態が、ページ再読み込み・再ログインをまたいで残っていないか
  （`isViewingFranchise`は常にfalseへリセットされる設計になっている）。

## 診断ログの使い方

`hydrateFromSupabase`は`console.info`で`[sync-hydrate] start / success / failure`のログを出す
（role・authenticatedCompanyId・viewingCompanyId・selectedStoreId・availableStoreCount・appVersion等。
パスワード・JWT・メールアドレスは出力しない）。他ユーザーから不具合報告を受けたときは、まず
ブラウザのdevtools consoleでこのログを確認し、どの会社・店舗を見ている状態でどんな取得結果になって
いるかを特定してから調査を始める。
